# Field run, 0.2.0, 2026-09-11: open performance questions for 0.2.1

A snapshot of one run, kept because it raised questions worth answering, not as a citable
result. Every number here is a median of 3 cold-cache runs on minipc on 2026-09-11 and stops
being true the moment the tree, the field or the box moves. `docs/benchmarks.md` owns the
method and deliberately carries no tables; this file is the exception that documents a
regression hunt, and it dates itself so nobody quotes it later as a constant.

Raw data beside this file:

- `scale-0.2.0-20260911.csv` and `.manifest.md`
- `media-0.2.0-20260911.csv` and `.manifest.md`
- `scale-0.1.6-20260908.csv` and `.manifest.md` (the baseline compared against)
- `media-0.1.6-20260908.csv` and `.manifest.md`

Entrant under test: `flea` at `b992e764`, working tree DIRTY (four files: the keymap cap-order
fix and its test, plus two edits to `tools/flea-readme-shots`). None of them touch Rust or the
listing path, so none plausibly moves memory; recorded because the manifest says DIRTY.

## The confound this run cannot rule out

**The harness pins the TUI bracket's terminal font and does not pin the GUI's Omarchy
base-size.** `kitty.conf` sets `font_size 12` for every TUI entrant precisely so the number does
not depend on whatever somebody set last week, and the GUI bracket has no equivalent: Flea reads
`~/.config/omarchy/shell.toml` from the live home, while every GTK and Qt rival uses its own font
settings and is therefore immune. A base-size change between two runs moves Flea's numbers and
nobody else's, which is the exact shape of this result.

The operator's base-size was changed during this period, 14 to 20 and back to 14. The 2026-09-11
run was at 14. **The 2026-09-08 baseline's value is not recorded in its manifest**, so the two
runs cannot be proven to have been taken at the same scale.

What the confound does not explain: the scale fixture holds 100,000 `.txt` files and zero
thumbnailable entries, so no entrant drew a thumbnail at all, yet Flea's PSS there still rose
27.0 MiB. Thumbnail or icon size cannot account for that column.

The media settle is separately not like-for-like: Flea's thumbnail count doubled, 36 to 74, so
it is doing more work than the run it is being compared against, and more than `nemo`'s 60.

## What 0.2.1 should do, in order

1. **Pin the GUI scale in the harness** and record it in the manifest, the way `font_size 12` is
   pinned for the TUI. Until that exists, no two GUI runs are comparable and every Flea-only
   delta has this alternative explanation. This is the prerequisite, not the investigation.
2. **Probe fixed cost against per-row cost.** Measure PSS on an empty directory for 0.1.6 and
   0.2.0 at one pinned scale. If the gap is already there with zero rows, it is startup cost: a
   new import or a component now resident. If it only appears on the 100,000-row listing, it is
   per-row.
3. **If it is startup cost, suspect an import.** `reference_quickshell_memory_tuning` in the KB
   measured QtMultimedia at roughly 20 MB to import and nothing else, and
   `reference_qt_loads_every_image_plugin_on_the_first_decode` is the other known fixed cost.
   0.2.0 added the dual pane, the Open With card, the Permissions card and the keymap sheet;
   any of them can pull a module that 0.1.6 never loaded.
4. **Read PSS with the huge-page caveat.** `reference_thp_inflates_quickshell_pss` measured two
   thirds of this app's PSS as transparent huge page rounding on FileView thread stacks, so a
   27 MiB delta may be a smaller true allocation rounded up. Confirm against the arena count
   before optimising anything.
5. Only then decide whether the media settle regression is real or is the doubled thumbnail
   count doing exactly what it should.
