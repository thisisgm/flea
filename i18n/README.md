# Flea catalogs

`en/flea.json` defines flat keys, `%1` through `%N` arguments, and cardinal plural objects with an `other` form. Other catalogs use the same keys and arguments; their plural category names can differ. Empty or missing translations fall back to English per string. The English plural rule applies when the English string supplies that fallback.

MIME descriptions normally come from shared-mime-info in the selected language. Norwegian `no` also accepts its `nb` provider entry. `mime.png` supplies a localized fallback when the provider lacks a translation and is registered in every catalog. Provider translations take precedence over that fallback. `mime.markdown` is a narrow optional override: English declares its source and Japanese supplies the HIG correction `Markdown 文書` (CHANGES.md:2800). Other catalogs omit it and keep their MIME description or its untranslated fallback. `I18n::mime_comment` reads only an explicitly present translation; it never substitutes the English catalog value. Manifest and quality checks require the Markdown key in English and Japanese and allow its absence elsewhere.

Run `python3 -B tools/flea-i18n-manifest` after reviewing catalog changes. The manifest maps each language to `flea:key` entries containing the first 12 hexadecimal characters of the English SHA-256 hash, matching Omarchy's hash convention. Regeneration refreshes the `en` source index and records the initial hash when a translated key first appears. Existing translation hashes retain the English source they were translated against. Hashing a plural object uses sorted JSON keys with Python's default separators and unescaped Unicode, as Omarchy does.

`python3 -B tools/flea-i18n-manifest --check` checks the source index, key parity, value shapes, and argument parity. It warns by language and key when a translation's hash is stale and exits 0 if no structural error exists. After updating a translation, run `python3 -B tools/flea-i18n-manifest --mark de folder.empty items.count` to record only those keys against current English. `flea:` prefixes are also accepted. Run `python3 -B src/i18n/manifest_tests.py` for the manifest history regressions.

Shared desktop words can be looked up directly as `omarchy:shell.common.search`, `omarchy:menu.apps.label`, or `omarchy:keybindings.Close window`. A Flea string can also contain an entire reference. Reference values in catalogs are checked against Omarchy's English source; use `--omarchy-path DIR` for an uninstalled checkout and `--reference REFERENCE` for references used directly by callers.

`python3 -B tools/flea-i18n-roster [locales.json]` checks exact membership and metadata against the fixture roster in `src/i18n/fixtures/locales.json` and fails if any language has no Flea catalog or a catalog names an unknown code. During extraction, and in the `locale` CI suite, explicitly passing `--warn-only` reports missing catalogs without failing. Malformed rosters, invalid directions, changed membership and broken provenance still fail.

`python3 -B tools/flea-i18n-roster --omarchy-path /usr/share/omarchy --check-installed --require-final-pin` is the release gate. `OMARCHY_PATH` supplies the default source root when `--omarchy-path` is omitted. Installed checks compare the roster and plural rules with the pinned bytes, then resolve every catalog reference and every literal direct Rust reference in core and GUI sources against each installed language, including nested menu fields and keybinding names. Missing or empty target-language values fail without English fallback. Test fixture sources are excluded. `--source-dir DIR` can select caller roots for isolated checks. `--warn-only` cannot be combined with the final-pin check; with installed checks it only turns missing catalogs into a warning, and installed checks also refuse an alternate roster file. The existing `locale` CI suite runs the installed check against the recorded pin, requires `jq`, and exercises the roster regression controls. `i18n-quality` also discovers `tests/i18n/test_roster.py` when that suite is integrated.
The `locale` CI suite runs `--check-installed --warn-only`, without `--require-final-pin`, so a catalog that has not landed yet is reported and does not fail the commit; installed hashes and references still fail it.

`ci/i18n-pin.json` records the upstream repository, tag and full commit, plus the SHA-256, upstream path and local path of each fixture. Roster counts are always read from the pinned fixture, never recorded separately. `--require-final-pin` refuses any release-candidate tag, so the release gate fails while the pin names one. To re-pin, fetch the tag into an Omarchy Git checkout and run `python3 -B tools/flea-i18n-roster --repin TAG --omarchy-path CHECKOUT`. It resolves the tag to its commit, copies both fixtures from that commit's Git objects (the working tree is ignored) and rewrites the pin. Then rerun the locale and quality suites plus the existing all-code plural equality test. Installed packages need no Git metadata: the gate checks their data bytes against the recorded fixtures.

The core reads `$OMARCHY_PATH/default/i18n/locales.json` and `$OMARCHY_LANGUAGE_FILE` or `${XDG_CONFIG_HOME:-$HOME/.config}/omarchy/language`. Omitting or invalidating the language selects English. `Paths::catalogs` lists catalog roots in priority order; defaults search `$FLEA_I18N`, executable-relative `share/flea/i18n` and system data directories. The compile-time source tree is also searched in debug builds or when the executable sits in that tree's `target/` directory. Call `I18n::poll_changed` from the caller's event loop to follow changes without a core thread.

The eight standard XDG place names use `places.row.desktop`, `documents`, `downloads`, `music`, `pictures`, `videos`, `templates` and `public` under that prefix. Their translations come from the corresponding capitalized messages in the [xdg-user-dirs 0.19 catalogs](https://user-dirs.freedesktop.org/releases/xdg-user-dirs-0.19.tar.xz), with `nb` supplying `no` and `es` supplying `es-MX`. Greek Desktop uses the source phrase's noun alone, `Επιφάνεια`, to fit the existing rail label slot. That source has no Irish `Downloads` message, which retains English. The `PROJECTS` role uses `places.row.projects`, translated from the `Projects` message in the [xdg-user-dirs 0.20 catalogs](https://user-dirs.freedesktop.org/releases/xdg-user-dirs-0.20.tar.xz) with the same provider mapping. Upstream leaves all nine words untranslated for `bn`, `fil`, `ms`, `si`, `sw`, `ur` and `uz`. For `bn`, `ms`, `si`, `sw` and `uz` they come from Ubuntu's [Launchpad translations of xdg-user-dirs](https://translations.launchpad.net/ubuntu/+source/xdg-user-dirs), with Malay Desktop from the GTK catalog and Uzbek Downloads from Firefox's shorter folder name, which fits the rail label slot. `ur` follows the [CLE Urdu localization glossary](https://cle.org.pk/software/localization/OSS/ossGlossary.html), Firefox's Urdu folder names, Ubuntu's Urdu Unity lens and the catalog's own word for videos. `fil` follows Firefox's Tagalog folder names, Ubuntu's Filipino Unity lenses and the catalog's own word for pictures, and keeps the loanword `Desktop` as Firefox does. Standard role and English folder-name pairs are translated at display time. A custom folder name, a bookmark label and a volume label remain the user's data.

`tr` reads a string, `tr_args` substitutes caller arguments, and `trn` inserts the formatted count as `%1`. In `trn_args`, additional arguments start at `%2`. `Locale` supplies number, grouped count, decimal size and local date formatting. Dates keep `YYYY-MM-DD HH:MM` and use the roster's digits. glibc locale handles do not change the process locale; absent generated locale data falls back to conventional number grouping and the C locale for fixed-form dates.

The existing core plural equality test uses installed Omarchy data when available and otherwise `src/i18n/fixtures`. It compares all roster codes for counts 0 through 10000 against `plural.jq`. Fixture identity is recorded in `ci/i18n-pin.json`; the test's `bf9ee5c` fallback label predates that record. A missing `jq` prints an explicit skip in the core test, but is a hard failure in the locale CI suite and cannot satisfy release acceptance.

Runtime catalog and roster documents are limited to 1 MiB, 16384 total object members and array elements, and 32 levels of nesting. Duplicate members count toward the limit and the last value wins. Parsing uses a forward cursor and hashed object insertion; it never scans prior members for each key. Files exceeding a limit are refused with a diagnostic and ordinary English fallback. The release regression loads a representative complete-language budget of 4096 labels, errors and plural messages through `I18n::load` three times, with a 250 ms limit per run; it also checks prompt refusal of a 3920001-byte catalog.
