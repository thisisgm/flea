# Headless search instrument

The entry point is `campaign.py`, also available through the standalone Cargo launcher for the host broker. The product source remains pinned to `0ebbcffae14609a3663c90db6d5f73c5e86c97a4`. `upstream-inputs.json` records the imported engine and roster source hashes before integration. Imported historical entry points are retained as provenance, not used by this collector.

Run through `cargo-west.sh WORKTREE run --manifest-path tools/flea-searchbench/Cargo.toml -- ARGS`. Pin `.superpowers/cgw-host` to `pin:east2` or `pin:west` with the current broker. No GUI or minipc is involved. `--build-stage` builds a marked archive of the pinned product with the executor-ready metrics patch and the stage seam. It does not edit the product checkout. `--prepare` creates or verifies the registry under `/home/gm/flea-work/bench-corpora`. An existing registry is checked against the live identities before reuse. The source label is `flea-source`, never the old 682-entry rival source fixture.

Supply `--engine-build`, `--flea-bin`, `--matcher-bin`, `--walker-bin`, `--fzf`, `--fd` and `--rg`. The engine build must include the pinned current rival adapters, historical rich profile and tagged 0.3.12 anchor. The rebuilt tagged anchor is labeled `flea-0.3.12`, with source provenance, and does not claim installed-core identity. Rival binaries require the libraries from their recorded build environment. Missing inputs stop the campaign before timing. Preflight verifies binary and source receipts, pinned external tool versions and native engine library resolution. If the Arch-built rivals do not resolve their libraries natively, run within the recorded image with a same-host cold helper outside it.

All 16 engine configurations are retained, with the fresh and equal-history groups paired against their matching candidate profile. Every rival is paired with a fresh candidate process, A/B on even runs and B/A on odd runs. There are two five-pair pilot batches and 30 measured pairs per corpus, stage, rival and cache mode. Query p50 and p95 are reduced within a process before the run-clustered bootstrap. `runs.jsonl` records order, load immediately before and after each pair, capability limits and raw per-run metrics. Batches above load 4 are flagged; pairing reduces order bias but cannot guarantee background-load cancellation. Both ranking entry points use `fair/eligibility.py`: a performance winner requires at least 30 matched run IDs and exactly five run observations in each pilot batch for each entrant and metric. The paired 95% bootstrap interval must clear the larger of twice the largest per-entrant pilot median shift and the instrument resolution. Time floors follow the clock units, kernel ticks retain their tick floor, and campaign PSS has a 1024-byte floor. Missing or undersized pilots cannot rank. `summary.json` retains descriptive intervals, admission reasons and thresholds. Quality is top-350 reciprocal target rank, reported descriptively without a performance winner. Coverage remains an independent eligibility gate. ripgrep keeps its files-only diagnostic clock and cannot win a full-coverage index comparison. Matcher memory includes the driver and its descendant processes, including fzf.

The matcher candidate speaks the same O/Q/A/P/X contract as the rival adapters. It builds the production compressed `Index` from the shared paths and calls `Session::query`, which invokes the actual matcher, pruning, prior ranking and incremental query logic. Stage priors are empty and all path-only inputs are marked as files, matching the roster's input contract. This is a matcher stage, not an engine or product measurement.

The walker candidate calls the production `searchwalk::walk`, which fills and finalizes its compressed index. Rivals retain their traversal and common arena sink. Index/build clock boundaries differ in representation and are recorded as such. ripgrep remains a files-only census and receives no directory-coverage credit.

Cold collection uses BENCH-07's same-host request, SHA256, context, freshness and timestamp validation in both the helper and collector. It requires noninteractive permission to drop this host's page cache. The helper never changes the hostname, never targets minipc and never silently substitutes a warm run. Do not run it on a shared host without owning its cache-drop window.

For an image-bound campaign, use `--external-cold-helper`, mount the run and corpus roots at their actual host paths, and give the container the actual host's hostname. Run `cold-controller.py RUN_ROOT` on that same host. This disables the in-container helper; a missing external controller times out and cannot become a cold result. `--resolve-locks` is an explicit offline Cargo lock maintenance action, separate from timed collection; `--build-rosters` subsequently requires locked builds and prints the resolved lock bytes with its receipt.

## Measurement limits

- Engine passive watch freshness: the adapters do not export reliable recursive watcher health, mutation epochs and apply/push timestamps. A standing-result observation could be timed headless, but the current adapter cannot distinguish an unhealthy watcher or establish apply and push clocks. Relist and query polling are not passive freshness. These cells are unsupported, not wins or ties.
- Cancellation: close acknowledgement and generation supersession can be observed, but neither proves that the execution worker and background walkers are idle. There is no native idle stamp. Worker-idle cancellation remains unsupported for every engine. Matchers and walkers have no product session or persistent watcher.
- Walker memory: one-shot rival adapters expose peak RSS, while the product seam can read PSS at index completion. These are different metrics and the collector does not rank them together. Missing steady PSS is unsupported, not zero.
- GUI presentation, installed binary identity and user-perceived repaint latency are outside this headless engine stage.
